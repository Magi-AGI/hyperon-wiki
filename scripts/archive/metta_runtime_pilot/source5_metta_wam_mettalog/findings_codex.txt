2. S5.Q1 evaluator - [EVAL-PROLOG-BACKTRACKING-NONDET]

MeTTaLog evaluation is Prolog-native and nondeterministic. The direct evidence is not a separate explicit work-stack implementation; it is SWI-Prolog backtracking plus `findall`, `call_nth`, `member`, and predicate dispatch.

Evidence:

- `prolog/metta_lang/metta_eval.pl:528-535` routes evaluation through `eval_10`, with hybrid compiler hooks only when enabled.
- `prolog/metta_lang/metta_eval.pl:559-561` uses `call_nth(eval_10(...), Nth)` for enumerating alternatives.
- `prolog/metta_lang/metta_eval.pl:831` collects candidate definitions with `findall(guarded_defn(... metta_defn ...))`.
- `prolog/metta_lang/metta_eval.pl:4484-4487` collects rule expansions with `findall((rule(...)), call_nth(get_defn_expansions(...), Nth), XXB0L)` and then evaluates the collected bodies.
- `prolog/metta_lang/metta_compiler_lib.pl:929-932` implements `superpose` through `member/2`.
- `prolog/metta_lang/metta_compiler_lib.pl:952-971` implements `collapse` through `findall`.

Verdict rationale: The evaluator is fundamentally a Prolog backtracking engine with MeTTa-specific dispatch wrappers. The optional compiler path does not make this a Rust-like stepping interpreter or an explicit work-queue evaluator.

3. S5.Q2 compiler - [COMPILER-OPTIN-INTERPRETER-DEFAULT]

The compiler/transpiler is real, but not default.

Evidence:

- `prolog/metta_lang/metta_interp.pl:1269` defines compile option default as `'false'`, with allowed values `false`, `true`, `hybrid`, and `full`.
- `prolog/metta_lang/metta_compiler.pl:2` describes "MeTTa to Prolog transpilation".
- `prolog/metta_lang/metta_compiler.pl:47` routes assertions through `compiler_assertz`.
- `prolog/metta_lang/metta_compiler.pl:201` says `option_value(compile, false)` selects `interp`.
- `prolog/metta_lang/metta_compiler.pl:205` says `option_value(compile, full)` selects `compiler`.
- `prolog/metta_lang/metta_compiler.pl:1593-1604` implements `compile_for_exec`.
- `prolog/metta_lang/metta_compiler.pl:1619-1645` compiles MeTTa definitions into compiled predicate records and Prolog clauses.
- `prolog/metta_lang/metta_compiler.pl:1867-1886` implements `compile_for_assert`.
- `prolog/metta_lang/metta_eval.pl:523-527` treats `compile=hybrid` and `compile=true` as hybrid interpreter/compiler mode.

Verdict rationale: MeTTaLog has a large compiler/transpiler surface, including WAM-ish `wam-body` handling, but the default option is interpreter mode.

5. S5.Q4 types - [TYPES-GRADUAL-OPTIONAL]

MeTTaLog carries and uses type information, but strict runtime checking is option-gated and mixed with dynamic inference/guessing.

Evidence:

- `prolog/metta_lang/metta_compiler_lib.pl:735-835` carries typed builtin signatures for arithmetic and boolean operators.

Verdict rationale: Types are not merely comments, but enforcement is optional/gradual rather than uniformly strict.

10. S5.Q9 0.2.x quirks

10.1 Q-1 bind! + new-space - [QUIRK-DIVERGENT-SEMANTICS]

Evidence:

- `prolog/metta_lang/metta_eval.pl:1960-1968` creates a new space through `oo_new('space', [], KB)`.
- `prolog/metta_lang/metta_eval.pl:2846-2866` implements `bind!` by resolving the name and calling `nb_bind`.
- `prolog/metta_lang/metta_compiler_lib.pl:979-983` defines compiler-library `bind!` and `new-space`.

Interpretation: The operators exist, but the implementation is a Prolog object/NB-value model rather than Rust `GroundingSpace` semantics. I do not call this "fixed" without running a behavioral test, but it does not share the same substrate as the S1 Rust quirk.

10.2 Q-2 cond - [QUIRK-FIXED]

Evidence:

- `git grep` for `cond` found no `cond` builtin in active `prolog/metta_lang/*.pl` or `*.metta`.
- `prolog/metta_lang/metta_compiler_lib.pl:638-642` implements `if`.
- `prolog/metta_lang/metta_compiler_lib.pl:688-730` implements `case`.
- `prolog/metta_lang/metta_eval.pl:2100-2134` routes `switch` to `case` and implements case evaluation.
- `prolog/metta_lang/metta_compiler_lib_stdlib.pl:36` declares `switch`.

Interpretation: The exact `cond` surface is absent; MeTTaLog uses `if`/`case`/`switch`. This is "fixed via absence/replacement" in the same sense used for prior runtime sources.

10.3 Q-3 catchall multi-reduction - [QUIRK-REPRODUCED]

Evidence for reproduction:

- `prolog/metta_lang/metta_eval.pl:4484-4487` collects all matching rule expansions with `findall` + `call_nth`.
- `prolog/metta_lang/metta_eval.pl:4512-4517` then iterates `member(rule(...), XXB0L)`.
- `prolog/metta_lang/metta_eval.pl:4560-4584` expands definitions through multiple `get_defn_expansions*` paths.
- `prolog/metta_lang/metta_eval.pl:4490-4496` handles `metta_eq_def` by finding all matching `H->B0` pairs and then iterating through `member`.

Countervailing evidence:

- `prolog/metta_lang/metta_compiler_lib.pl:193-244` has a typed-function path that can score and order candidates by `OrderFittest`.
- `prolog/metta_lang/metta_typed_functions.pl:177` has a nondeterministic fallback, and `:197` has default function types with `OrderFittest`.

Interpretation: MeTTaLog has a most-specific typed-function subsystem, but the main interpreter definition path still enumerates all matching rule bodies. For the S1 catchall multi-reduction quirk, that is closer to reproduced than to MeTTaTron's [QUIRK-DIVERGENT-SEMANTICS] specificity-filter behavior.
